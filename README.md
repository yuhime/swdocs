# SWDOCS

A simple, lightweight Rust tool for effortlessly generating API documentation from the swagger.json files produced by your tsoa
 projects.

### Why SWDOCS?

When you're building an API with tsoa, you already have a swagger.json describing your endpoints, schemas, parameters, and responses.

So why write and maintain a separate API document?

I needed to provide documentation for an API project and realized that the information was already available in swagger.json. Instead of installing a large collection of tools or setting up a complicated documentation pipeline, I decided to build a small, fast parser that does exactly what I need.

That's SWDOCS.

## ✨ Features

[X] Fast — Written in Rust with performance in mind.

[X] Lightweight — No need for a huge dependency stack.

[X] Swagger-based — Uses your existing swagger.json.

[X] tsoa-friendly — Designed with tsoa-generated Swagger files in mind.

[X] Simple — One tool, one purpose.

## Installation
```bash
$ git clone git@github.com:yuhime/swdocs.git
$ make install
```

## 🚀 Usage

simple parse (no extra args)
```bash
swdocs swagger.json
```
ignore per tags/path/schema using glob pattern
```bash
swdocs -t "*oauth*" -p "/api/private" # ignore by tag, path
```
The basic idea is simple:

swdocs swagger.json

## Example

Given a swagger.json generated by tsoa:

{
  "openapi": "3.0.0",
  "paths": {
    "/users": {
      "get": {
        "summary": "Get users"
      }
    }
  }
}


SWDOCS parses the specification and turns it into readable API documentation.

## 🎯 Motivation

Most API projects already have a machine-readable description of their API.

Maintaining another document manually means:

More work

More things to keep synchronized

More opportunities for documentation to become outdated

SWDOCS aims to keep things simple:

Write your API → generate swagger.json → generate your documentation.
